The problem with the standard snippet

The Google Analytics 4 snippet that Google gives you has two parts: an external script, gtag/js?id=G-XXXX, and an inline block that calls gtag('config'). Both run as soon as the browser parses them. By the time your banner paints, gtag.js has been downloaded, the _ga cookie is set and the first page view has been sent. A banner placed on top cannot undo that.

Blocking means the browser never executes those scripts until the visitor accepts analytics. There is a simple, standard way to do it: a script whose type is not a JavaScript type is not executed, and not even downloaded. type="text/plain" turns a script into inert text.

Three changes to your head

First, load cookieowl as the very first script, synchronously. Second, change the type of both parts of the GA snippet to text/plain. Third, add data-cookieowl="analytics" so cookieowl knows which category releases them:

When the visitor accepts analytics, cookieowl replaces each inert script with a live copy, in document order. The inline block runs right away; external scripts without async are waited for, so a script that depends on another never runs too early. If the visitor never accepts, nothing is requested from Google.

When you cannot edit the snippet

Plugins, themes and tag managers often inject Google Analytics from their own code. For those, auto mode recognizes the URL of the script when it is added to the page, whether by the HTML parser or by document.createElement, and holds it the same way:

Auto mode knows gtag.js, the older analytics.js, Google Tag Manager and Google Ads, along with the Meta Pixel, Microsoft Clarity, Hotjar, LinkedIn Insight, the TikTok Pixel and YouTube and Vimeo embeds. Two honest limits: it must load before the tracker (so keep cookieowl first, synchronous, in the head), and the browser preload scanner may download, but not run, a tracker written directly in the HTML. Explicit text/plain markup avoids even that download.

Prefer the explicit markup for the scripts you control and keep auto mode as a safety net for the ones you do not.

Verify it in DevTools

Open a private window, open the developer tools on the Network tab and type google in the filter. Load your page. The list must stay empty. In the Application tab, the cookie list must not contain _ga or _ga_ entries. Then click Accept all: gtag/js and a collect request appear, and the cookies are set.

You can also check from the console. Before a choice, cookieowl.accepted('analytics') is false and the GA scripts still have type="text/plain". After accepting, they are replaced and marked with data-cookieowl-done.

Withdrawal: deleting _ga and stopping the script

A script that already ran cannot be unloaded, which is why withdrawal needs two steps. cookieowl erases the cookies it knows for the category (for analytics that includes _ga, _ga_*, _gid and _gat* on your domain and parent domains), and then reloads the page because analytics scripts ran on it. After the reload, the scripts are inert again.

cookieowl.init({
  // In a single page app you may prefer to clean up yourself.
  reloadOnWithdraw(categories) {
    if (categories.includes('analytics')) window.location.reload();
  },
});
